# Ingesting a new question source

This repo's question bank lives in `questions.json`, generated by `scripts/parse_security_bank.py` from a small number of canonical `*_clean.md` files. Every new source (a PDF, a messy ChatGPT export, a raw text dump someone shares) goes through the same pipeline before it reaches `ia_clean.md` or `quiz_clean.md`. Do not invent a new one-off script if the source is shaped like most exam-review banks; use the reusable tool first.

## Step 1: try the reusable tool first

`scripts/ingest_source.py` extracts, deduplicates and appends the "N. question / A-D options / Answer: X" shape (the shape most PDF-to-text extraction produces). Run a dry run first:

```sh
python scripts/ingest_source.py \
  --source "data_files/received qus/<the file>.pdf" \
  --target ia_bank --batch <short_label> --section "<Person>'s Exam Review" \
  --dry-run
```

`--target` is `ia_bank` (appends to `data_files/ia_bank/ia_clean.md`) or `quiz_bank` (appends to `data_files/quiz_bank/quiz_clean.md`). Reading a PDF directly requires PyMuPDF importable as `fitz`; if the environment's default `python`/`python3` doesn't have it, find one that does (check `pip show pymupdf` under other interpreters on the machine) rather than skipping straight to pre-extracting text by hand.

The dry run reports: how many questions were extracted, how many are unique against the current 700+-question bank (and against duplicates within the source itself), and, critically, which unique survivors have no explanation and still need one written.

If the source's format doesn't match (true/false-heavy ChatGPT transcripts with "Thought for Ns" noise, PDF exports with duplicated intro blocks, or anything genuinely irregular), read `scripts/convert_chris_ia.py`, `scripts/convert_desmond_ia.py` and `scripts/convert_chris_quiz.py` for three different real examples of handling awkward formats, then decide whether to extend `ingest_source.py`'s extractor or write a one-off script modeled on those. Prefer extending the shared tool when the new format is likely to recur.

## Step 2: never fabricate an unanswerable question

If a question's answer or options were genuinely lost (a PDF extraction gap, garbled OCR, a stray fragment with no recoverable stem), drop it rather than guess. Document what was dropped and why, in the source file's own header comment if it has a TODO note, or in a `<!-- TODO -->` comment at the point in `ia_clean.md`/`quiz_clean.md` where it would have gone. Never invent plausible-sounding options or an answer for content that isn't actually in the source.

If a source's transcript is fundamentally corrupted at the question-text level (a garbled voice-dictation session, for example, where only fragments of an AI's spoken-back explanation survive but the real question was never captured in text), exclude the whole file rather than reconstructing questions from topic clues. `data_files/received qus/Chris/quiz_5.md` is the documented example of this.

## Step 3: every unique question needs a real explanation

The dedup step alone doesn't finish the job. Every question that survives into the bank must have a specific, accurate "Intuition"/"Reason" explaining *why* the answer is correct, not a generic placeholder repeated across many questions. `SET5_clean.md` once had all 100 fill-ins sharing the literal string "Fill-in precision is critical on Sakai exams." as their reason; that was a real bug caught and fixed, treat any repeated boilerplate reason the same way.

Write a `{normalized-80-char-body-prefix: explanation}` JSON file (see `data_files/ia_bank/sk_ia_explanations.json` for the format) and pass it via `--explanations-json` to fill gaps without re-touching anything already explained. `normalize_text` (from `scripts.parse_security_bank`) is what produces the key; when in doubt, print the keys the tool expects rather than guessing punctuation.

## Step 4: regenerate and verify

```sh
npm run build:bank
```

Then run the full verification pass, see the `verify-changes` skill for the exact commands and what each one is checking for. Confirm the total question count only changed by the number of genuinely new unique questions (dedup against the existing ~700+ bank should drop most of a typical source; if a "new" source shows suspiciously few duplicates against material that clearly overlaps in topic, double check the extraction isn't silently corrupting question bodies in a way that defeats the duplicate-detection key).

## Step 5: don't forget the app can't see it yet

Adding a batch name to `parse_security_bank.py` is not enough by itself. `src/main.tsx`'s `sourceBanks` array is a second, independent list the UI uses to filter Practice, Read-with-answers and Deck Export; Mock exam samples from the raw bank directly and isn't affected by it. A source only wired into the parser but missing from `sourceBanks` is present in `questions.json` yet invisible in most of the app, this has happened more than once in this repo's history. Either add the new batch to `sourceBanks`, or (the pattern now preferred for small contributor sources) skip a separate batch entirely and append the unique survivors directly into `ia_clean.md`/`quiz_clean.md` so they're just part of the existing `iabank`/`quizbank` batch and need no UI change at all.
